Detailed Description

Duration and easing of an animated change, CSS transition style.

Transitions are opt-in: a layout or a component without transition definitions behaves exactly as without this class, every change applies at once.

Spec strings

A spec string is "<ms> <easing>", e.g. "250 inOutQuad": the duration in milliseconds (digits and an optional decimal point), whitespace, the easing name. Also valid:

  • "250" a duration alone is linear
  • "0 ..." a duration of 0 is instant
  • "none" instant

Easing names (case sensitive, implemented by the functions in gin_easing.h):

  • linear
  • inQuad, outQuad, inOutQuad
  • inCubic, outCubic, inOutCubic
  • inQuart, outQuart, inOutQuart
  • inQuint, outQuint, inOutQuint
  • inSine, outSine, inOutSine
  • inCirc, outCirc, inOutCirc
  • inExpo, outExpo, inOutExpo
  • inBack, outBack, inOutBack
  • inElastic, outElastic, inOutElastic
  • inBounce, outBounce, inOutBounce

Presets

A layout json's top-level "transitions" object names specs. Several layout files of one LayoutSupport merge their presets in load order. Presets are looked up from the animated component up through its parents, so nested layouts can define their own and still use their ancestors'. The preset name "default" is special: it applies to every animated property under that layout that no "transition" entry covers.

"transitions": { "quick": "100 outQuad", "glide": "650 inOutCubic", "default": "250 inOutQuad" }

Per component "transition"

A component entry's "transition" is either

  • a string, a preset name, an inline spec or "none": applies to every animated property of the component
  • an object, one value per property name, like CSS transition-property: { "bounds": "glide", "alpha": "quick", "colour": "none" }

Property names: "bounds" (the layout moving and resizing the component), "alpha" and "scale" (the layout's entries of that name and States' values; "scale" is also AnimatedScale's default), "imageFilter" (AnimatedImageFilter's default), and any name an Animated or Crossfade value in code was given.

Inheritance

The transition for a property of a component is the first match walking from the component up through its parents:

  • a string "transition" matches every property (so "none" stops the walk, instant)
  • an object "transition" matches the properties it lists; others continue upwards If nothing matches, the "default" preset applies, else the change is instant. A container's transition therefore applies to all its descendants unless they override it.

An object may set what the descendants inherit instead with the key "descendants" (a string or a per-property object, same rules). It doesn't apply to the component itself, e.g. a page that slides in while the rows inside it keep jumping when they relayout: { "bounds": "glide", "alpha": "glide", "descendants": "none" }

{
"transitions": { "quick": "100 outQuad", "glide": "650 inOutCubic" },
"components": [
{ "id": "panel", "transition": "glide", "components": [
{ "id": "title" }, // glide
{ "id": "knob", "transition": { "bounds": "quick" } }, // bounds quick, rest glide
{ "id": "meter", "transition": "none" }, // instant
{ "id": "list", "transition": { "alpha": "quick", "descendants": { "bounds": "quick" } } }
// list: alpha quick, bounds glide; its children: bounds quick, alpha glide
] }
]
}

◆ setPresets()

void Transition::setPresets ( juce::Component & c,
const juce::var & presets )
static

Sets a component's presets, exactly as a layout json's top-level "transitions" does for the component its LayoutSupport lays out: an object of name -> spec, or a JSON string of one.

They apply to the component and everything inside it, also children added later. A void var clears them. Invalid specs assert. A LayoutSupport replaces the presets of the component it lays out on every pass, so set them on another component.

For code-built UIs without a layout json above them:

// The grid of game tiles, built in code: presets, timings and the tiles' hover state
GameGrid()
{
gin::Transition::setPresets (*this, R"({ "hover": "60 inOutQuad", "fade": "300 outQuad" })");
gin::Transition::set (*this, juce::JSON::parse (R"({ "descendants": { "scale": "hover", "imageFilter": "hover", "alpha": "fade" } })"));
gin::States::setForChildren (*this, juce::JSON::parse (R"({ "hover": { "scale": 1.05, "imageFilter": "contrast 20" } })"));
}
// Each tile, added whenever; it inherits the grid's transitions and states
class GameTile : public juce::Component
{
public:
void paint (juce::Graphics& g) override { cover.draw (g, getLocalBounds().toFloat()); }
private:
gin::AnimatedImageFilter cover { *this }; // its image set elsewhere
};

◆ setGlobalEnabled()

void Transition::setGlobalEnabled ( bool enabled)
static

Switches every transition in the app on or off, e.g.

off for software renderers or slow machines. Off, everything that would animate (Animated, Crossfade, AnimatedScale, AnimatedImageFilter, the layout's bounds, alpha and scale, States, box shadows) jumps straight to its target, its owner repainting once per change, and the vertical blank driver doesn't tick at all. Switching off makes running transitions jump to their targets at once. The initial value is GIN_TRANSITIONS_ENABLED_BY_DEFAULT: off on Linux (JUCE's software renderer only), on elsewhere, unless the app defines it.
